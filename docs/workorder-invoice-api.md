# Work Order Invoice API Documentation

APIs for issuing invoices against existing work orders, tracking invoice payment status, recording payments, and uploading payment statements/proofs.

## Authentication

All endpoints require:

| Header | Required | Description |
| --- | --- | --- |
| `X-API-Key` | Yes | Mobile app API key |
| `Authorization` | Yes | `Bearer <access_token>` |

## Roles

| Action | Roles |
| --- | --- |
| Read invoices/payments | `super_admin`, `regional_manager`, `manager` |
| Create invoices | `super_admin`, `regional_manager` |
| Update invoice status | `super_admin`, `regional_manager` |
| Record payments | `super_admin`, `regional_manager` |
| Update payment status | `super_admin`, `regional_manager` |
| Upload payment statements | `super_admin`, `regional_manager` |

Branch access is enforced from the linked work order or invoice.

## Response Envelope

Success:

```json
{
  "success": true,
  "data": {}
}
```

Error:

```json
{
  "success": false,
  "error": "message"
}
```

## Enums

### Invoice Status

```text
draft, issued, cancelled, void
```

### Invoice Payment Status

Maintained automatically from confirmed payments.

```text
unpaid, partially_paid, paid, overpaid, refunded
```

### Payment Method

```text
bank_transfer, cash, cheque, credit_card, debit_card, upi, other
```

When `method` is `other`, `other_method` is required.

### Payment Record Status

```text
pending, confirmed, failed, reversed, rejected
```

Only `confirmed` payments count toward `paid_amount`, `balance_amount`, and `payment_status`.

## Invoice Number

Invoice numbers are generated by the backend in financial-year format:

```text
01/2026-27
02/2026-27
```

The sequence is scoped by branch and financial year.

## 4. Update Invoice Status

Marks an invoice as `draft`, `issued`, `cancelled`, or `void`.

### Endpoint

```http
PATCH /api/v1/work-orders/invoices/{invoiceID}/status
```

### Request Body

```json
{
  "status": "issued",
  "pdf_url": "http://localhost:8080/uploads/invoices/01-2026-27.pdf"
}
```

`pdf_url` is optional. When status becomes `issued`, `issued_at` is set automatically. When status becomes `cancelled` or `void`, `cancelled_at` is set automatically.

### cURL

```bash
curl -X PATCH "http://localhost:8080/api/v1/work-orders/invoices/{invoiceID}/status" \
  -H "X-API-Key: your-mobile-app-api-key" \
  -H "Authorization: Bearer your-access-token" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "issued"
  }'
```

## 8. Upload Payment Statement

Uploads a statement or proof file for a payment.

### Endpoint

```http
POST /api/v1/work-orders/invoice-payments/{paymentID}/statements
```

### Multipart Fields

| Field | Required | Description |
| --- | --- | --- |
| `statement` | Yes | PDF/image statement file |
| `notes` | No | Optional notes |

Allowed file types:

```text
PDF, PNG, JPG, JPEG, WEBP
```

Max upload size: `10MB`

### cURL

```bash
curl -X POST "http://localhost:8080/api/v1/work-orders/invoice-payments/{paymentID}/statements" \
  -H "X-API-Key: your-mobile-app-api-key" \
  -H "Authorization: Bearer your-access-token" \
  -F "statement=@/path/to/bank-statement.pdf" \
  -F "notes=Bank statement for June payment"
```

### Response

```json
{
  "success": true,
  "data": {

    "statement_url": "http://localhost:8080/uploads/invoice-payment-statements/7d2ad604-3778-4827-8370-e2829079aee2/statement-a1b2c3.pdf",
```

## Validation Errors

Common validation failures:

| Error | Cause |
| --- | --- |
| `invalid invoice_date: use YYYY-MM-DD` | Invalid `invoice_date` |
| `invalid due_date: use YYYY-MM-DD` | Invalid `due_date` |
| `invalid payment_date: use YYYY-MM-DD` | Invalid `payment_date` |
| `invoice item description is required` | Custom invoice item has no description |
| `duplicate invoice item line_no` | Duplicate line number in custom invoice items |
| `other_method is required when method is other` | `method` is `other` without `other_method` |
| `statement file is required` | Multipart upload missing `statement` |
| `only PDF, PNG, JPG, JPEG, and WEBP statement files are allowed` | Unsupported statement file type |

## Status Codes

| Code | Meaning |
| --- | --- |
| `200` | Successful read/update |
| `201` | Created |
| `400` | Invalid JSON body |
| `401` | Missing/invalid API key or JWT |
| `403` | Role or branch access denied |
| `404` | Work order, invoice, or payment not found |
| `422` | Validation error |
| `500` | Server/database error |
